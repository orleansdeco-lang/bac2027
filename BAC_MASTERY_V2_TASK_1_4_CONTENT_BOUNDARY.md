CANONICAL CONTENT BOUNDARY\n\n### What IS Canonical Content?\nCanonical content consists of **declarative, version-controlled educational facts and assessment instruments**:  \n1. Syllabi, streams, subjects, and coefficient rules.  \n2. Thematic curriculum topics and chapters.  \n3. Observable pedagogical skills with actionable repair protocols.  \n4. Atomic learning objectives and scientific concepts.  \n5. Prerequisite DAG declarations.  \n6. Authentic student misconception traps.  \n7. Assessment items (questions, options, interactive configs, solutions).  \n8. Ministerial scoring rubrics.  \n9. Pedagogical resources (lessons, summary cards, repair guides).  \n10. Isomorphic retest twin pairings.  \n\n### What is NOT Canonical Content?\n- **Learner State:** Student proficiency, streaks, mastery scores, active errors, review schedules (`LearnerState ≠ Content`).  \n- **Student Interactions:** Raw clicks, response times, selected radio buttons (`Attempt ≠ Question`).  \n- **Cognitive Observations:** Evaluated vectors (`Evidence ≠ Question`).  \n- **Adaptive Decisions:** Priority scores, roadmap sequences, next-best-action recommendations (`Decision ≠ Content`).  \n- **UI State / Visuals:** React component state, theme, scroll position, modal toggles (`UI ≠ Content`).  \n- **Database Rows:** Supabase `practice_attempts` or `student_progress` caches (`DB Cache ≠ Content Authority`).  \n\n---\n\n## 5. AUTHORING VS PUBLISHED VS RUNTIME\n\nIn BAC Mastery V2, content follows a strictly unidirectional progression:\n\n```mermaid\nflowchart LR\n    A[1. AUTHORING<br/>Git-tracked TS/JSON files<br/>in src/domain/v2 & packages] --> B[2. REVIEW & VALIDATION<br/>Pedagogical & Schema Checks<br/>VerificationStatus == verified] \n    B --> C[3. PUBLISHED<br/>Immutable, Versioned Release<br/>ContentLifecycle == published] \n    C --> D[4. RUNTIME READ MODEL<br/>V2 Domain Entity Projections<br/>Available to Practice Runners] \n    D --> E[5. APPLICATION UI<br/>Headless Rendering in<br/>React Components] \n```\n\n### Strict Invariants:\n1. **Runtime may ONLY consume Published content.**  \n2. **Runtime cannot author, mutate, or revise content.**  \n3. **Draft content is quarantined from runtime assessment engines.**  \n\n---\n\n## 6. LEGACY COMPATIBILITY BOUNDARY\n\nDuring the transition to V2, existing legacy content files in `src/data/` remain the physical authoring store. However, their relationship to the V2 domain is strictly defined:\n\n```text\n         LEGACY SOURCE (src/data/)  <-- Physical authoring files\n                     │\n                     ▼\n         READ-ONLY ADAPTER LAYER     <-- Pure projection functions\n                     │\n                     ▼\n         V2 CANONICAL DOMAIN        <-- Authoritative domain representation\n```\n\n> [!IMPORTANT]\n> **NON-INVERSION PRINCIPLE:**  \n> Legacy content **does NOT gain canonical authority** merely because a read-only adapter can parse it.  \n> The adapter exposes legacy records to V2 while explicitly tracking lossy conversions, missing metadata, and safe defaults.\n\n---\n\n## 7. CANONICAL ID RULES\n\n1. **Language Independence:**  \n   IDs are semantic Latin ASCII tokens (e.g. `snv_protein_synthesis`, `math_asymptotes_limits`). They are completely invariant to whether the student views Arabic or French prompts.\n2. **Stability & Immutability:**  \n   Once published, an entity ID must never be mutated or reassigned. Modifying an ID breaks prerequisite DAGs, error histories, and retention schedules.\n3. **Namespace Prefixing:**  \n   - Skills: `{subject}_{descriptor}` (e.g. `physics_rc_differential_equation`)  \n   - Topics: `{subject}_topic_{descriptor}` (e.g. `math_topic_functions`)  \n   - Practice Questions: `pq-{subject}-{descriptor}` (e.g. `pq-math-asymptotes-01`)  \n   - Retest Questions: `rq-{subject}-{descriptor}` (e.g. `rq-math-asymptotes-01`)  \n   - Misconceptions: `misc_{skillId}_{descriptor}`  \n   - Rubrics: `rubric_{questionId}`  \n\n---\n\n## 8. CURRICULUM VERSION BOUNDARY\n\n- **Current State:** The legacy codebase specifies academic year strings (e.g. `"2024-2025"`) or coarse versions (`version: 1`). There is no cryptographic syllabus commit hash.  \n- **V2 Boundary:** The architecture designates `CurriculumVersionId` as a formal entity. In Task 1.4, missing version hashes are explicitly classified as `UNAVAILABLE` rather than synthetically fabricated.\n\n---\n\n## 9. LIFECYCLE BOUNDARY\n\nThe canonical content lifecycle recognizes 5 distinct operational states:\n1. `draft`: Authored in Git, under drafting; excluded from runtime practice.\n2. `in_review`: Undergoing pedagogical calibration or Arabic linguistic validation.\n3. `validated`: Approved against official ministerial syllabus benchmarks.\n4. `published`: Active in runtime assessment and diagnostic engines.\n5. `deprecated`: Retained for historical telemetry analysis; superseded by syllabus revisions.\n\n**Lifecycle Safety Rule:** The adapter layer performs **zero automatic promotions**. Content authored as unverified remains unverified.\n\n---\n\n## 10. PROVENANCE BOUNDARY\n\nEvery canonical content entity must maintain traceable origin:\n- `sourceType`: `ministry`, `official_curriculum`, `official_exam`, `original_bac_mastery`, etc.\n- `sourceId`: Reference decree, ministerial circular, or ONEC past exam identifier.\n- If provenance is absent in legacy records, it must be marked `UNAVAILABLE` rather than invented.\n\n---\n\n## 11. RIGHTS BOUNDARY\n\nBAC Mastery strictly enforces intellectual property classification:\n- `original`: Authored by BAC Mastery; fully proprietary.\n- `official_reference`: Citation or metadata reference to public Algerian exam papers.\n- `licensed`: Educational content licensed from approved partners.\n- `unknown`: Undeclared rights status.\n\n**Quarantine Invariant:** Content with `rightsStatus: "unknown"` must be quarantined as non-distributable. The platform will never assume public domain.\n\n---\n\n## 12. QUESTION VERSION BOUNDARY\n\n- **Question Identity:** Stable Question ID (`QuestionId`).\n- **Question Version:** Monotonically increasing revision counter (`version: number`).\n- Modifying a question's stem, distractors, or answer key increments its `version`. If the pedagogical construct changes fundamentally, a new `QuestionId` must be created.\n\n---\n\n## 13. RESOURCE BOUNDARY\n\n`Resource ≠ Question`.  \nA lesson, worked example, PDF guide, summary card, or video explainer is an **instructional resource**. It provides conceptual scaffolding. Questions are **evaluative instruments**. Resources cannot produce attempts or evidence.\n\n---\n\n## 14.
